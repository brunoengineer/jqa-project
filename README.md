# QA Lobby

A **local-first QA agent workspace**. Turn short descriptions, tickets, diffs, and requirements into well-structured Markdown QA documents — bug tickets, test plans, test cases, coverage analyses, PR reviews, and more — using **Ollama** on your machine, or your existing **Claude** and **GitHub Copilot** plans when you want a stronger model, with no API keys or extra billing. OpenAI and the Claude API are also supported if you prefer pay-per-use keys.

The app runs on `http://127.0.0.1:3000`. There are no accounts and no database: projects and generated documents are plain JSON + `.md` files on disk. The agents come from [qa-agent-hub](https://github.com/brunoengineer/qa-agent-hub), the same prompts used in Copilot Chat and Claude Code.

## Features

- **12 QA agents** synced from qa-agent-hub, grouped into Tickets, Test design, Analysis, and Review.
- **LLM providers side by side:** Ollama (local, free, private), Claude (your Claude plan via Claude Code), GitHub Copilot (your Copilot plan), plus optional pay-per-use Claude API and OpenAI. Pick a provider and model for each generation; your choice is remembered per provider.
- **Live provider status:** the form shows whether the provider is ready, lists the models you can use (the models you've pulled into Ollama, or the ones your Copilot plan includes), and warns if the selected model isn't available.
- **Agent-specific forms** with required fields and **file attachments** for long inputs (requirements, logs, diffs, CSVs).
- **Projects and history:** every generated document is saved to disk, grouped by agent, and can be reopened, copied as Markdown, downloaded as `.md`, or deleted.
- **Editable agent prompts:** tune any agent's instructions on the **Agents** page; **Reset to default** brings back the synced version.
- **Dark, modern UI** with a readable, Confluence-style Markdown viewer (tables, code blocks, checklists).

## Agents

| Category | Agent | Minimum input | Output |
|---|---|---|---|
| Tickets | **Jira Bug** | What happened (+ expected, steps) | Jira-ready bug report |
| Tickets | **Bulk Jira Bugs** | Issue list, report, or triage notes | One document with separate tickets |
| Tickets | **Jira Task** | What needs doing (+ component, priority) | QA task with acceptance criteria |
| Test design | **Test Approach** | Ticket or feature description | ISTQB-aligned approach: scope, levels, techniques, risks, exit criteria |
| Test design | **Test Plan** | Feature name + what it does | Full 12-section test plan |
| Test design | **Test Cases** | Feature or requirement | Precondition + Markdown table of manual tests |
| Test design | **Exploratory Charter** | Feature or risk area | Time-boxed charter with tours and heuristics |
| Analysis | **Coverage Analysis** | Requirements + existing test cases | Coverage estimate, gaps, recommendations |
| Analysis | **Automation Gaps** | Scope + current manual/automated coverage | Best automation candidates and recommended order |
| Analysis | **Root Cause Triage** | Failure summary (+ logs) | Likely cause, alternative hypotheses, next steps |
| Review | **Release Readiness** | Release name + test status | Go / go-with-risks / no-go with follow-ups |
| Review | **PR Review** | Raw diff (+ PR URL, existing comments) | Approval-risk report with proposed inline comments |

Three hub agents are **not** included because they need direct access to a codebase or must run tests: `write-tests`, `test-stability-check`, and `automation-health-check`. Use them from Claude Code or Copilot Chat inside the target repository.

## Setting up providers

You can set up any combination; the provider switch in each form shows which ones are ready.

### Ollama (local, default)

1. Install from <https://ollama.com> and make sure it's running (`http://localhost:11434`).
2. Pull at least one model:

   ```powershell
   ollama pull llama3.1      # or qwen3.5:9b, llama3.2, …
   ollama list
   ```

In the form, choose **Ollama**; the Model field suggests your pulled models and warns if the typed one isn't installed.

QA Lobby asks Ollama for an 8K-token context window (`OLLAMA_NUM_CTX`) so long agent prompts and pasted requirements aren't cut off. Raise it if you paste very large inputs and have the memory; lower it on small machines.

### Claude — your Claude plan (no API key, no extra cost)

The **Claude** provider runs the Claude Code CLI in headless mode (`claude -p`) with your own claude.ai login, so generations count against your **Claude Pro/Max plan's usage limits**, not API billing.

1. Have Claude Code installed and signed in once with your Claude account. The Claude Code **VS Code extension** is enough: QA Lobby finds the CLI bundled inside it automatically. It also finds a `claude` on your PATH or in `~/.local/bin`, or you can point `CLAUDE_CODE_PATH` at the executable.
2. Choose **Claude** in the form. The status line shows `Your Claude plan · <email>`.
3. Models: `opus` (default), `sonnet`, `haiku`. Sonnet and Haiku use up plan limits more slowly.

Each run has **all tools disabled**, runs in an empty temp folder with no settings or MCP servers loaded, and isn't saved as a session. QA Lobby also removes `ANTHROPIC_API_KEY` from the CLI's environment, so it can never switch to pay-per-use billing, even if that key is set in `.env.local`.

### Claude API (pay per use, optional)

Only if you want API billing instead of your plan:

1. Create a key at <https://console.anthropic.com>.
2. Add it to `qa-lobby/.env.local`:

   ```ini
   ANTHROPIC_API_KEY=sk-ant-...
   ```

3. Restart `npm run dev`, choose **Claude API**. The default model is `claude-opus-5`; `claude-sonnet-5`, `claude-haiku-4-5`, and `claude-fable-5-1` are suggested too.

Responses are streamed server-side, so long documents don't time out. On Claude Opus 5, Opus 5.5 and Fable 5.1, the server-side refusal fallback is turned on, so a request declined by a safety classifier is automatically retried on another model.

### GitHub Copilot (your subscription)

Uses the official [`@github/copilot-sdk`](https://github.com/github/copilot-sdk), which runs the Copilot CLI runtime bundled with the package and bills your own Copilot plan. You need an active Copilot subscription. Sign in **once**, in either of two ways:

- **Interactive:** run `npx @github/copilot` in a terminal, type `/login`, and follow the device flow. Then quit the CLI.
- **Token:** create a fine-grained personal access token with the **Copilot Requests** permission and add it to `.env.local`:

  ```ini
  COPILOT_GITHUB_TOKEN=github_pat_...
  ```

Choose **Copilot** in the form; the status line shows `Signed in as <login>` and the Model field lists the models your plan includes. Each generation runs in a short-lived session with **all tools disabled**, using the agent prompt as the full system message. The session is deleted afterwards, so it doesn't clutter your Copilot CLI history.

### OpenAI

```ini
OPENAI_API_KEY=sk-...
# OPENAI_BASE_URL=https://api.openai.com/v1   # optional; must support the Responses API
```

### Environment variables

| Variable | Default | Purpose |
|---|---|---|
| `CLAUDE_CODE_PATH` | auto-detected | Path to the Claude Code executable (Claude plan provider) |
| `ANTHROPIC_API_KEY` | — | Claude API key (pay per use; never passed to Claude Code) |
| `COPILOT_GITHUB_TOKEN` | — | Copilot token (not needed after `/login`) |
| `OPENAI_API_KEY` | — | OpenAI API key |
| `OPENAI_BASE_URL` | `https://api.openai.com/v1` | OpenAI-compatible base URL |
| `OLLAMA_BASE_URL` | `http://localhost:11434` | Ollama server |
| `OLLAMA_NUM_CTX` | `8192` | Ollama context window (tokens) |
| `LLM_PROVIDER` | `ollama` | Fallback provider for API calls that omit `provider` |

Restart the dev server after changing `.env.local`.

```powershell

Open <http://127.0.0.1:3000>. The dev server listens on `127.0.0.1` only. If PowerShell blocks npm scripts, use `npm.cmd run dev`.

|---|---|

## Using QA Lobby

1. **Create a project** on the home page (e.g. the feature or release you're testing).
2. **Pick an agent** from the left sidebar inside the project.
3. **Choose the provider and model** at the top of the form. The dot shows the provider's status: green means ready, amber means it needs setup (the reason is shown next to it).
4. **Fill in the fields.** Required ones are marked with `*`. Where you see **+ attach files**, you can add text files (`.txt`, `.md`, `.csv`, `.json`, `.log`, `.diff`, …); their contents are included in the prompt, but the files themselves aren't stored.
5. Click **Generate** (or press **Ctrl + Enter**). A progress bar shows the provider, model, and elapsed time.
6. The document opens in the viewer and is saved to disk. From there: **Copy MD**, **Download .md**, or **Delete** (click twice to confirm). **← New …** returns to the form; the **History** list under it shows every document for that agent.

To tune an agent, open **Agents** in the header, expand it, edit, and **Save changes**. A **customized** badge marks overridden agents; **Reset to default** restores the synced prompt.

## How it works

```
Browser (TaskForm)
   │  builds "## <field label>\n<value>" blocks + attached file contents
   ▼
POST /api/llm/generate  { provider, model, taskId, prompt }
   │  1. loads the agent prompt (saved override → prompts/<taskId>.md)
   │  2. sends it as the system prompt, and the form as the user message:
   │       Claude     → Claude Code CLI `-p`, --system-prompt-file, no tools (your plan)
   │       Claude API → Messages API (streamed), `system`
   │       Copilot → SDK session, systemMessage mode "replace", no tools
   │       OpenAI  → Responses API, `instructions`
   │       Ollama  → prepended to the prompt (keeps a Modelfile SYSTEM such as qa-agent)
   │  3. strips a single wrapping ```md fence if the model added one
   ▼
{ markdown }  →  POST /api/projects/{id}/outputs  →  <outputId>.md + <outputId>.json
```

## Agent prompts and syncing from qa-agent-hub

The files in [`qa-lobby/prompts/`](qa-lobby/prompts/) are **generated** from a local clone of qa-agent-hub:

```powershell
cd qa-lobby
npm run sync:agents                               # expects ..\..\qa-agent-hub
npm run sync:agents -- --hub C:\path\to\qa-agent-hub
```

For each agent, [`scripts/sync-agents.mjs`](qa-lobby/scripts/sync-agents.mjs):

1. reads `.claude/commands/<agent>.md`,
2. inlines the shared guidance sections from `.claude/CLAUDE.md` that the command references (QA Core, Documentation Output, Jira, Test Design, Automation),
3. drops sections that only make sense in a chat tool ("If No Input Provided", "File Output") and file-naming rules, since QA Lobby always sends input and saves files itself,
4. appends QA Lobby's output rules: single-shot generation, no follow-up questions, state assumptions, and return only the Markdown document.

Run it again whenever you update the hub, then commit the changed prompts. Customizations saved on the Agents page are stored separately in `data/prompts/` and aren't touched by a sync.

## Optional: the `qa-agent` Ollama model

[`llm/models/qa-agent`](llm/models/qa-agent) is an Ollama Modelfile that builds a QA-specialized model on top of `llama3.2` with a senior, ISTQB-aligned test analyst persona.

```powershell
ollama pull llama3.2
ollama create qa-agent -f llm/models/qa-agent
```

Then choose **Ollama** and select `qa-agent` in the Model field.

## Local data

All user data lives in `qa-lobby/data/`, which is created on first use and **gitignored**:

```
qa-lobby/data/
├── projects.json                      # index of projects
├── projects/<projectId>/
│   ├── project.json
│   └── outputs/
│       ├── <outputId>.md              # the document
│       └── <outputId>.json            # agent, title, provider/model, form input, createdAt
└── prompts/<agentId>.md               # prompt overrides saved on the Agents page
```

- **Backup:** copy `data/`. **Reset:** stop the server and delete `data/`.
- JSON files are written atomically (temp file + rename), and updates to `projects.json` are serialized, so concurrent requests can't corrupt the index.
- Documents created before the qa-agent-hub sync (task ids like `create-bug-ticket`) are shown under their matching new agent automatically. Old prompt overrides under those ids are no longer used.

## HTTP API reference

| Method | Endpoint | Body / query | Response |
|---|---|---|---|
| `POST` | `/api/llm/generate` | `{ provider?, model, prompt, taskId? }` — provider: `ollama` \| `claude-code` \| `copilot` \| `claude` \| `openai` | `{ markdown }` |
| `GET` | `/api/llm/models?provider=<id>` | — | `{ available, models, message? }` |
| `GET` / `POST` | `/api/projects` | POST `{ name }` | `{ projects }` / `{ project }` |
| `DELETE` | `/api/projects/{projectId}` | — | `{ ok: true }` |
| `GET` / `POST` | `/api/projects/{projectId}/outputs` | POST `{ taskId, markdown, title?, input? }` | `{ outputs }` / `{ output }` |
| `DELETE` | `/api/projects/{projectId}/outputs/{outputId}` | — | `{ ok: true }` |
| `GET` | `/api/prompts` | — | `{ prompts }` |
| `GET` / `PUT` / `DELETE` | `/api/prompts/{taskId}` | PUT `{ content }`; DELETE resets to default | `{ taskId, content, source }` / `{ ok: true }` |

Smoke test (PowerShell, dev server running):

```powershell
curl.exe -s http://127.0.0.1:3000/api/llm/generate `
  -H "content-type: application/json" `
  -d '{"provider":"ollama","model":"llama3.1","taskId":"jira-bug","prompt":"## What happened?\n\nLogin button does nothing on Safari."}'
```

## Adding a new agent

1. **Prompt:** add the command to qa-agent-hub and list its id in `AGENTS` in [`scripts/sync-agents.mjs`](qa-lobby/scripts/sync-agents.mjs), then run `npm run sync:agents`. For an app-only agent, write `qa-lobby/prompts/<id>.md` by hand.
2. **Register it** in [`src/tasks/registry.ts`](qa-lobby/src/tasks/registry.ts) with `id`, `name`, `description`, `category`, a 3-letter `code`, and its `fields` (`rows` for a textarea, `required`, `allowFiles`).

That's all: the sidebar, form, history, and Agents page are generated from the registry.

## Troubleshooting

| Symptom | Fix |
|---|---|
| Ollama: "not reachable" / amber status | Start Ollama and check <http://localhost:11434> |
| Ollama: "“llama3.1” isn't available" | Click one of the suggested models, or `ollama pull llama3.1` |
| Claude: "Claude Code CLI not found" | Install the Claude Code VS Code extension or CLI, or set `CLAUDE_CODE_PATH` |
| Claude: "Not signed in" | Run `claude` once and log in with your Claude account |
| Claude: usage limit reached | Your plan limit resets over time; switch to `sonnet`/`haiku`, Copilot, or Ollama meanwhile |
| Claude API: "no credentials found" / `401` | Check `ANTHROPIC_API_KEY` in `qa-lobby/.env.local` and restart |
| Copilot: "Not signed in" | `npx @github/copilot` → `/login`, or set `COPILOT_GITHUB_TOKEN`; then reload the page |
| Copilot: model error | Pick a model from the Model suggestions — they're the ones your plan includes |
| OpenAI: `401` / missing key | Check `OPENAI_API_KEY` in `.env.local` and restart |
| Output is cut off or ignores the input (Ollama) | Raise `OLLAMA_NUM_CTX`, or use a larger model |
| Very slow generation | Expected on CPU-only machines with local models; try a smaller model or a cloud provider |
| Port 3000 in use | `npm run dev -- -p 3001` |
| `npm` blocked in PowerShell | `npm.cmd run dev`, or `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned` |

## Known limitations

- **No streaming to the browser:** the UI waits for the full document, and a progress bar shows the elapsed time.
- **Documents are read-only in the UI.** Regenerate, or edit the `.md` file in `data/`.
- **Attachments are read as plain text:** PDF, DOCX and XLSX files aren't parsed.
- **Single-user and local only**, with no authentication.
- **No automated test suite yet.**
